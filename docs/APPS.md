# Apps on Finch's frameworks

Which of Apple's own apps (`/System/Applications`, with Utilities) have every import
Finch's frameworks provide, and what the rest lack, ranked by how many apps each gap
blocks. Generated by `tools/app-sweep.py --markdown /System/Applications
/System/Applications/Utilities` over the build Mac's macOS 26.4, counting each app's
main executable and the frameworks it carries; weak imports don't count. Regenerate it
in any commit that changes what Finch's frameworks export. Third-party apps are swept
the same way locally (`tools/app-sweep.py` with no arguments) but aren't listed here.

## The 1.0 app set

Chosen 2026-10-15: Apple's own apps (`/System/Applications` and Utilities, these tables),
including the 19 "Ready" ones, and the build Mac's most-used third-party apps: cmux,
ChatGPT, Claude, Claude Usage, Google Chrome, Discord, Dialpad, Zed, Gemini, Tailscale and
Xcode (Minecraft and Steam as games). The aim is that any Mac app runs as on macOS, by
matching Apple's frameworks, not by tuning Finch to these apps; they're the acceptance
tests. Chrome, Discord, Claude and Dialpad carry Chromium (Electron), so they share one
target. Third-party apps are mostly plain arm64 (Apple's are arm64e); both run on the
arm64e system images, and `tools/check-imports.py` reads whichever slice an app has. A
local sweep of /Applications (2026-10-15) finds 6 of 36 apps with every import, the rest
blocked most by WebKit (17 apps), VideoToolbox (14), Accelerate and MetalKit (13 each),
CoreData, AuthenticationServices and SecurityInterface (11 each).

Having every import is the first gate, not the last: an app that passes still has to be
run and checked (`docs/ROADMAP.md`, the app milestone).

## Launched in the VM

The "Ready" apps, launched one after another in QEMU by `tools/vm/app-launch.py --ready` (each
copied into the image from this Mac with `FINCH_HOST_APPS`, run for 45 seconds). A titled
level-0 window is the normal success result. The checker also accepts the known system UI
for Screenshot and Bluetooth File Exchange, and no app window for the four direct-launch
helpers below. As of 2026-10-15, all 19 pass:

| App | Result |
|---|---|
| AirPort Utility, Calculator, ColorSync Utility, Console, Digital Color Meter, Font Book, Grapher, Image Capture, Magnifier, Script Editor, Stickies, Terminal, TextEdit | titled window (Terminal's window takes about 30 seconds on its first launch, archiving its settings) |
| Screenshot | full-screen capture overlay, untitled and level 1000 |
| Bluetooth File Exchange | level-8 dialog; the VM has no Bluetooth, so it says Bluetooth is unavailable. On this Mac it opens “Select File to Send.” |
| Apps | no app window; the Apps browser is hosted by Spotlight and Dock |
| Mission Control | no app window; the desktop overview is opened by the system shortcut |
| Siri | no app window on direct launch; Siri's UI appears after Siri is activated |
| Time Machine | no app window without the backup UI or a backup disk |

`app-launch.py` accepts Screenshot only with a level-1000 window, Bluetooth File Exchange
only with a level-8 window, and the four no-window cases only when there is no visible
app-level window. This keeps an unrelated empty or untitled window from making an app pass.
Mission Control is normally entered with Control-Up Arrow or a trackpad gesture. Apps opens
the app browser through Spotlight. Siri must be activated before it shows its assistant UI.
Time Machine's backup view needs a backup disk. These launches are system surfaces or
service-driven apps, not document-window apps.

Calculator, TextEdit and Stickies are checked further by `tools/vm/test-calculator.sh`,
`tools/vm/test-textedit.sh` and `tools/vm/test-stickies.sh`. Since 2026-10-26 Apple's apps
run sandboxed, as on macOS (all 19 still come up): TextEdit opens, saves, autosaves and
exports to PDF from its container; Stickies keeps its notes there, asks its own XPC
service where they live, and copies to and pastes from the pasteboard (`pbcopy` and
`pbpaste` on the other side).
